# Workspace guide

This file explains how the app is built and how the parts fit together. It is
for a developer picking the project up without reading every line first.

The app is a personal calendar and school planner. It is a static site: one
HTML file, one stylesheet, one script, plus a bell-schedule data file and a
service worker. There is no framework, no build step and no npm install. All
data is kept in the browser's `localStorage`. Sync is optional and off by
default.

## Files

| File | What it holds |
| --- | --- |
| `index.html` | The static shell: top bar, five empty view containers, tab bar, lock layer, sheet layer |
| `app.css` | Every style. Themes are CSS custom properties under `[data-theme]` |
| `app.js` | All logic: storage, dates, rendering, events, focus sessions, sync |
| `bell.js` | Bell schedule tables for Del Norte High School. Sets `window.BELL` |
| `sw.js` | Service worker. Caches the shell for offline use. `CACHE` must be bumped when assets change |
| `manifest.webmanifest` | PWA metadata (name, icons, colors) |
| `icons/` | App icons, generated by `tools/make_icons.py` |
| `sync/worker.js` | Cloudflare Worker. Stores one encrypted blob per sync code |
| `README.md` | User-facing description and setup notes |

`bell.js` loads before `app.js`. `app.js` runs inside an IIFE in strict mode,
so nothing leaks onto `window`.

To run it:

```bash
python3 -m http.server 8000
```

## How rendering works

There is no virtual DOM and no component system. The pattern is:

1. `index.html` holds five empty `<section class="view">` elements, one per tab.
2. A render function builds an HTML string and assigns it to `innerHTML`.
3. Clicks are caught by one delegated listener on `document`, which reads
   `data-act` from the closest element.

`render()` is the single entry point. It sets the top-bar title, shows the
active view, hides the others, and calls the render function for the current
tab. Every view except the calendar rebuilds itself completely on each render.

Element attributes drive behavior:

- `data-act` — what a click does (`open`, `toggle`, `add`, `tab`, `class`, …)
- `data-kind` / `data-id` — which item the action applies to
- `data-type` — which item type a form or add button is for

Text that comes from the user is always passed through `esc()` before it is
put into an HTML string.

## App state

```js
const state = {
  tab: 'home',      // which view is showing
  classId: null,    // set while looking at one class inside Schedule
  selected: today() // the day picked on the calendar, as YYYY-MM-DD
  month, year       // which month the calendar grid is showing
};
```

`state` is not persisted. The app always opens on Home with today selected.

## Data

Everything is stored under one `localStorage` key, `planner.v1`. Sync settings
live separately under `planner.sync`, and the theme under `planner.theme`.

The database is a plain object of arrays:

```js
{
  classes:   [{ id, name, color, updatedAt }],
  homework:  [{ id, title, classId, due, details, done, completedAt, updatedAt }],
  notes:     [{ id, text, classId, date, updatedAt }],
  projects:  [{ id, name, due, status, description, updatedAt }],
  events:    [{ id, title, date, details, updatedAt }],
  schedule:  [{ id: 'p3', period: 3, classId, room, teacher, updatedAt }],
  overrides: [{ id: '2026-09-14', date, key, updatedAt }],
  focus:     [{ id: 'session', startedAt, endedAt, totalMs, breaks, breakMs, startedOn, updatedAt }],
  deleted:   { [id]: timestamp }        // tombstones
}
```

Rules that matter:

- Dates are plain `YYYY-MM-DD` strings in local time. There is no timezone
  math anywhere except the bell schedule, which is pinned to Pacific.
- Every item carries `updatedAt`. `touch(item)` sets it. Sync merges per item,
  newest edit wins.
- Deleting an item writes a tombstone into `deleted` so the delete survives a
  merge instead of being resurrected by another device.
- `schedule` rows use a fixed id (`p1`…`p5`), so a period slot is replaced
  rather than duplicated.
- `overrides` rows use the date as the id, for the same reason.
- The focus session uses a fixed id, `session`. There is only ever one.
- `projects` have a three-state `status`: `todo`, `doing`, `done`, defined by
  `STATUSES` with a percentage used for progress display.

Storage helpers:

- `load()` reads and repairs the stored object. Missing arrays fall back to
  empty ones.
- `persist()` writes to `localStorage` after a 60 ms debounce. Used for data
  that came in from sync.
- `save()` = `persist()` + mark the record dirty + schedule a sync. Used for
  every local edit.
- `sweepCompleted()` deletes homework that has been checked off for more than
  two days, through the normal tombstone path.

## Navigation

The tab bar at the bottom has five buttons. The middle one, Home, is drawn as
a raised circle. Tapping a tab sets `state.tab`, renders, scrolls to the top
and replays the view entrance animation.

| Tab | View id | Purpose |
| --- | --- | --- |
| Calendar | `#view-calendar` | Month grid plus what is on the selected day |
| Schedule | `#view-schedule` | Today's bell schedule, periods, and classes |
| Home | `#view-home` | The hub the app opens on |
| Focus | `#view-focus` | Set up and run a focus session |
| Tasks | `#view-tasks` | Every homework item and project, grouped by deadline |

The top bar holds the title (which doubles as a button), month arrows that
only appear on the calendar, a sync button and a theme button.

## Views

### Home

The default tab. Contents, top to bottom:

- A hero card showing the current bell period with a live countdown. Tapping
  it jumps to Schedule.
- An **Add homework** button, plus chips for Note, Project and Date.
- **Do tonight** — open homework due tomorrow.
- **Still due** — open homework due today or already late.

The hero redraws once a second through `tick()`. Only the countdown text and
the progress bar width are touched; a full redraw happens only when the
current block changes.

### Calendar

A six-week grid, rebuilt as one HTML string. Each day shows its number and up
to three colored dots for the items on it: homework and notes in their class
color, projects in purple, dates in amber.

Under the grid is the agenda for the selected day. When the selected day is
today it also lists **Overdue** and **Upcoming** (the next six unfinished
items within three weeks).

Interactions:

- Tapping a day moves the selection in place, without rebuilding the grid, and
  re-renders only the agenda with a soft animation.
- The arrows in the top bar change month, with a directional slide.
- A horizontal swipe on the grid does the same thing.
- Tapping the month title jumps back to today.

### Schedule

Two levels.

The list level shows a hero with the live countdown, then the whole day's
blocks with the current one highlighted and finished ones dimmed, then
**Classes & periods**: periods 1–5, any class without a period, and a **New
class** row.

The class level opens when a period or class row is tapped. It shows that
class's homework, its notes, its period/room/teacher row, and an edit row.
`state.classId` holds which class; the back link clears it.

How the schedule is picked for a day, in order: an override you set for that
date, then `BELL.byDate`, then `BELL.byWeekday`. **Change** writes an override
for today only.

All of the clock work runs in `America/Los_Angeles` through `Intl`, so the
countdown is right on a device set to another timezone, and DST is handled.

### Focus

A study session where the phone is deliberately blocked.

Setup is three `− value +` steppers: focus time, number of breaks, break
length. Values can also be typed. Out-of-range numbers are clamped by
`FOCUS_LIMITS`. A summary line reads the plan back.

Only the plan and the moment it started are stored. Every device derives the
current phase from the wall clock, so a device that was asleep is correct as
soon as it wakes.

- On a phone (`max-width: 820px` and a coarse pointer) the whole page is
  covered by `#lock`: red **DO NOT USE** while studying, blue **HAVE FUN**
  during a break, and an alarm state when a break has run out.
- On a computer nothing is blocked. A pill above the tab bar shows the phase
  and the time left.
- Stopping takes a deliberate hold: 7 s on the computer, 5 s on the phone (and
  only if the session was started there), 3 s to silence the alarm.
- Sound is unlocked by the tap that starts the session and kept alive by a
  silent looping audio element. The chime and alarm are scheduled on the audio
  clock, not with `setTimeout`, so a throttled tab still rings.

`focusTick()` runs every second for the whole life of the page. It repaints the
lock, keeps the desktop pill honest, and fires the chime and alarm.

### Tasks

The single place for everything that has to be finished: all homework and all
projects, in one list, grouped by deadline.

Groups, in order, each with a count in the header:

1. **Overdue** — open items whose due date has passed
2. **Today**
3. **Tomorrow**
4. **This week** — the next two to seven days
5. **Later**
6. **Done** — checked-off homework (kept two days) and finished projects

Each row shows the title, then a subtitle: the class name and details for
homework, or `Project · <status>` for a project. A due chip on the right shows
the deadline for groups where it is not already implied by the header:
`3d late` in red for overdue, a weekday for this week, a short date for later.

The circle on the left is the status control.

- Homework: tap to toggle done. Checking an item leaves it in place, crossed
  out, so the list does not jump under the finger. It moves into **Done** the
  next time the view is built.
- Projects: tap to cycle `Not started → In progress → Done`. The circle is
  empty, half filled, then ticked.

Tapping the rest of the row opens the edit sheet, the same one used everywhere
else. A **New task** row sits at the bottom; it opens the add sheet, where the
segmented control can switch the type to Project, Note or Date.

Groups fade up in sequence when the view is built. Status changes update only
the affected row and the group counts, so checking things off never rebuilds
the list.

## Sheets

One `#sheet` element does every form and picker. `openSheet(html, ctx)` fills
it, shows the wrapper, locks the page behind it and focuses the first field.
`ctx` records what the sheet is for; `submitForm()` reads it to decide what to
save.

`ctx.mode` is one of:

| mode | Sheet |
| --- | --- |
| `add` | New item, with a segmented Homework / Note / Project / Date control |
| `edit` | Existing item, with a Delete button |
| `class` | New or existing class, with the color grid |
| `period` | Assign a class, room and teacher to a period |
| `plan` | Pick today's bell schedule |
| `sync` | Sync setup and status |

Points worth knowing:

- The page behind is pinned with `position: fixed` and the scroll offset is
  restored on close, so it does not jump.
- `fitSheet()` listens to `visualViewport` and lifts the sheet above the iOS
  keyboard.
- The primary button is `position: sticky` at the bottom of the sheet, so it
  stays reachable in a tall form.
- The class dropdown includes a **New class…** option; picking it reveals a
  name field and `resolveClass()` creates the class on submit.
- Validation is one function, `flash(sel)`, which turns the field's border red
  and focuses it.
- Above 620px wide the sheet becomes a centered dialog instead of a bottom
  sheet.

## Item types

| Type | List | Date field | Where it shows |
| --- | --- | --- | --- |
| Homework | `homework` | `due` | Tasks, Home, Calendar, its class |
| Project | `projects` | `due` | Tasks, Calendar |
| Note | `notes` | `date` | Calendar, its class |
| Date (event) | `events` | `date` | Calendar |

New homework defaults to tomorrow, projects to a week out. If you are looking
at another day on the calendar, new items land on that day instead.

## Sync

Off until switched on, and there is no account. One random code, like
`4KP2-9TXQ-M7VB`, is both the name of the record and the key to it.

- The record name is `SHA-256('planner.id.v1|' + code)`, first 32 hex chars.
- The encryption key is PBKDF2 over the code, 120k iterations, into AES-GCM
  256. The blob is `base64(iv) + '.' + base64(ciphertext)`.
- The server therefore stores a name it cannot reverse and a blob it cannot
  read. Different codes are completely separate records.

`syncNow()` does: GET the record, merge what came back into the local db, then
PUT if anything changed locally. A `409` means someone wrote first: merge the
fresh copy and retry once.

`mergeInto()` is per item and per kind. Newest `updatedAt` wins, and anything
with a tombstone newer than its own `updatedAt` is dropped. Tombstones older
than about four months are forgotten.

Sync runs on open, ~2.5 s after an edit, when the app is backgrounded or comes
back, when the network returns, every five minutes while open, and every 15
seconds while a focus session is running.

The server is `sync/worker.js`, a Cloudflare Worker backed by a Durable Object
per code so the revision check is strictly consistent. Protocol:
`GET /<id>` → `{rev, blob}`, `PUT /<id>` with `{rev, blob}` → new `rev`, or
`409` with the current record.

Sync needs a secure context because it uses WebCrypto.

## Theme

Two themes, light and dark, driven by `document.documentElement.dataset.theme`
and CSS custom properties. The choice is stored under `planner.theme`.

An inline script in `<head>` applies the stored theme before the first paint,
and sets `theme-color` and `apple-mobile-web-app-status-bar-style` so iOS does
not paint a white status bar over a dark app. The dark background is pure
black so the two meet seamlessly.

## Animation

Animations are part of the design and should not be removed. They are kept
cheap on purpose: only `transform` and `opacity` are animated, so they stay on
the compositor. Nothing animates layout properties like `top` or `height`.

Where they are:

- `.anim-view` — the entrance for a view when a tab is opened
- `.anim-soft` — the agenda refresh when a calendar day is picked
- `.anim-left` / `.anim-right` — the directional slide when the month changes
- `rise` — the bottom sheet coming up; `fade` — the scrim, and the sheet on
  wide screens
- `pop` — the checkbox when homework is checked off
- Task groups fade up in sequence, using a small per-group delay
- `breathe` — the sync icon while syncing, and the focus pill's dot
- `lineIn` — the rotating reminder on the phone's lock screen
- `.is-holding .hold-fill` — the hold-to-confirm fill, driven by a CSS
  transition whose duration comes from the `--hold` variable

`replay(el, cls)` restarts an entrance animation on an element already on
screen: remove the class, force a reflow, add it back.

Everything is disabled under `prefers-reduced-motion: reduce`, except the
hold-to-confirm fill, which is feedback rather than decoration.

## Timers

| Timer | Period | What it does |
| --- | --- | --- |
| `tickTimer` | 1 s | Bell countdown. Only runs on Home and Schedule, and stops when the page is hidden |
| `focusWatch` | 1 s | Focus phase, lock screen, desktop pill, chime and alarm |
| sweep + sync | 5 min | Clears old completed homework and syncs |
| focus sync | 15 s | Faster sync while a session is running |
| `saveTimer` | 60 ms | Debounced write to `localStorage` |
| `syncTimer` | 2.5 s | Debounced sync after an edit |

## Things to preserve

- No dependencies, no build step. Everything must keep working from a plain
  static file server.
- The app must still work offline, with sync turned off.
- Dates stay as `YYYY-MM-DD` local strings. Only the bell schedule uses Pacific.
- Every local edit goes through `touch()` + `save()`, and every delete writes a
  tombstone, or sync will lose or resurrect data.
- Items keep their ids. Fixed ids (`p1`…`p5`, the override date, `session`)
  must stay fixed.
- Checked-off homework is not deleted straight away. It stays for two days.
- The escape helper `esc()` must be used on anything a person typed.
- The theme script in `<head>` must stay inline and stay first.
- `CACHE` in `sw.js` must be bumped whenever an asset changes, or clients keep
  the old files.
- Animations stay. Keep them on `transform` and `opacity`.
